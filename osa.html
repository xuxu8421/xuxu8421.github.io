Research workflow

Recording what triggered an intervention

The research workflow needed to collect signals, decide when to act, play a configured sound, and preserve enough context to review the event afterward. A working model alone could not provide that complete loop.

I built the application around the researcher’s task: connect equipment, configure an experiment, see the current state, and inspect a session.

DECISIONS

Device state and recovery

Keep inference and waveform writes off the capture callback

Audio callbacks write to a ring buffer; a worker runs model inference. BLE communication runs on its own asyncio loop. I connected acquisition, control, and recording through a thread-safe event bus, and moved waveform writes to a background thread.

Expose the runtime through explicit interfaces

FastAPI REST endpoints control devices and experiments. Periodic WebSocket snapshots feed Vue views for sensor freshness, controller state, and cooldown conditions, making disconnected or stale inputs visible.

Make interventions traceable

I modeled trigger, playback, observation, and cooldown as controller states. Timestamped JSONL events and compressed NPZ signal blocks preserve the context around each intervention.

IMPLEMENTATION

Acquisition and control

FastAPI provides REST controls and periodic WebSocket runtime snapshots to the Vue application. The runtime coordinates BLE acquisition, the pretrained YAMNet audio model, an intervention controller, and session storage.

The controller moves through trigger, playback, observation, and cooldown states. Connection recovery and stale-data indicators address failures that occur at the device boundary.

Events are appended to JSONL. A background writer flushes buffered waveforms to compressed NPZ blocks, moving waveform compression and block writes off the acquisition path.
