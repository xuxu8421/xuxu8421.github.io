Researcher workflow

From benchmark failures to training data

Evaluation results can surface incorrect answers without explaining which capability failed or what data would help. The product needed an analysis path from individual failures to interpretable, aggregated findings.

DECISIONS

Prototype and analysis logic

Prototype the analysis steps

I designed and implemented the LangGraph prototype linking reference reasoning, error diagnosis, capability grouping, and reporting, then iterated its analysis paths and prompts.

Let the available evidence determine the analysis

I adapted reference-generation and diagnosis paths to whether a dataset supplied an answer, a scoring rubric, both, or neither. I encoded the corresponding analysis and judging constraints in 30+ structured prompt templates.

Make capability findings specific enough to use

I defined capability labels around the task and action, with constraints against unsupported generalization. Reviewing 700+ reports surfaced approximately 100 issues; recurring reasoning and taxonomy failures became prompt revisions and engineering requirements.

My work covered the analysis workflow, LangGraph prototype code, prompt templates, report review, and requirements. I also provided templates for MCP operator decomposition; the engineering team implemented those operators.

Work delivered

Work delivered

Across the internship, I iterated the evaluation prototype, developed 30+ structured prompt templates, reviewed 700+ reports, and identified approximately 100 issues. This work turned recurring failure patterns into concrete product and prompt changes.

How I would evaluate the workflow

Measure whether a finding changes a researcher’s next decision, and evaluate agreement between human reviewers and automated capability labels. Pair those measures with time-to-action rather than report volume alone.
